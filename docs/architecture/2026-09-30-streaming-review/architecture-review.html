After: one interface, the ordering inside it

reserve-failed fallback to record

The _start_query caller can't get the order wrong.

Problem
The budget check runs before retrieval and the reservation runs after it, so concurrent callers can all pass the gate. The slot release is passed implicitly to the worker thread.
Solution
One allowance module: admit does the gate check, takes a slot, and reserves together. settle is idempotent and also releases the slot.
Wins
  • Locality: spend bugs in one module
  • Close gate/reserve race
  • Delete _gate/_reserve/_finalize/_record wrappers
  • Tests: admit/settle sequences, in-memory SQLite

Problem
The page component carries the stream protocol and its recovery logic, and it has no tests. The head/done field split is written out three times (Python, TS, fixtures).
Solution
An event-in, view-out reducer. The fetch and fixture sources become two adapters that yield the same events.
Wins

  • Table tests over event sequences
  • Catch delta-before-results ordering
  • Delete headOf/doneOf

4 · One owner for citation numbering and markers

Worth exploring in-process
  • mtg-api: llm.py build_context/source_label · citations.py cite_answer · enrich.py · main.py (3 enrich_citations sites)
  • mtg-web: lib/stream.ts MARKER · fixtures/index.ts L377–391 · +page.svelte L226–238
Before: "source n = result n−1" written in 4 places
After
NumberedSources: .context · .live() · .finalize(answer) → CitedAnswer
numbering · enrich after context · no mutation
draftCitations(draft, results)
client marker grammar
shared marker-case corpus (JSON) run by both test suites
Problem
Callers have to remember the order (enrich after context, cite before dump). The client and server marker grammars can drift apart.
Solution
The server returns a value from build_context that owns numbering and finalization. The client gets one grammar module, and both sides share a corpus of marker test cases.
Wins
  • Ordering bugs become impossible
  • Locality: numbering in one place
  • Drift caught by shared corpus

Top recommendation

Deepen the answer allowance, done inside the extracted query pipeline

The allowance is the only candidate where the shallow shape already causes a real defect: the gate check and the reservation are split around retrieval, and the slot release is passed implicitly to the worker thread. Those are money bugs. Extracting the pipeline gives the allowance a home and a test surface that doesn't go through HTTP. Do the web-side answer stream (3) next; it is independent.
